PR01 Walkthrough

Prueba de penetración completa sobre la máquina virtual vulnerable "Snakeoil", ejecutada íntegramente dentro de un entorno de laboratorio aislado (red host-only), con fines exclusivamente académicos.

#Pentesting #CTF #Flask #UPSLP

01 / Resumen

Objetivo y alcance

Evaluar de forma metódica la superficie de ataque de una aplicación web deliberadamente vulnerable, hasta confirmar el impacto máximo posible dentro del laboratorio.

◎

Objetivo

Máquina virtual "Snakeoil", desplegada en una red interna host-only sin salida a Internet, sin sistemas ni usuarios reales involucrados.

◈

Metodología

Cuatro fases secuenciales: Reconocimiento, Enumeración, Explotación y Post-explotación / Escalada de privilegios.

✓

Resultado

Se obtuvo acceso inicial a la aplicación, ejecución remota de comandos y, finalmente, acceso con privilegios de administrador (root) sobre el sistema objetivo.

Nota académica: por política de uso responsable, esta página documenta el proceso a nivel metodológico — herramientas, fases y clases de vulnerabilidad— sin reproducir payloads, credenciales ni comandos de explotación específicos. El detalle completo, dentro de lo permitido, está en el reporte formal en PDF.

02 / Metodología

Fases del walkthrough

Proceso documentado paso a paso, a nivel de técnica y herramienta.

01

Reconocimiento

Herramientas: netdiscover · nmap

Identificación del host objetivo dentro de la red interna del laboratorio mediante descubrimiento pasivo de tráfico ARP, seguido de un escaneo de puertos y servicios expuestos.

$sudo netdiscover -i eth0 $nmap -sV -p- <IP_objetivo>
02

Enumeración

Herramientas: gobuster · Burp Suite

Enumeración de directorios y endpoints sobre el servicio web detectado, seguida de un análisis del tráfico HTTP con proxy de interceptación para entender el flujo de autenticación de la aplicación (registro, login y manejo de sesión por token).

  • Se identificaron múltiples endpoints de una API REST interna.
  • Se observó un esquema de autenticación basado en JSON Web Tokens (JWT).
$gobuster dir -u http://<IP_objetivo>:<puerto> -w <wordlist>
03

Explotación

Vulnerabilidades: credenciales hardcodeadas · inyección de comandos

Durante la revisión del código fuente de la aplicación se identificaron valores sensibles embebidos directamente en el código, y un endpoint administrativo con validación de entradas insuficiente (basada en lista negra), lo que permitió lograr ejecución remota de comandos en el servidor.

  • Clase de vulnerabilidad: Hardcoded Secrets (CWE-798).
  • Clase de vulnerabilidad: OS Command Injection (CWE-78) por lista negra evadible.
  • Resultado: obtención de una shell remota sobre el host objetivo.
04

Post-explotación y escalada de privilegios

Técnica: reutilización de credenciales · configuración de sudo

Tras estabilizar el acceso remoto, se exploró el sistema de archivos local, encontrando una contraseña reutilizada entre el código fuente de la aplicación y las credenciales del sistema operativo, lo que permitió elevar privilegios hasta obtener una sesión como administrador (root) y confirmar el compromiso total del objetivo.

  • Clase de vulnerabilidad: reutilización de contraseñas entre servicios y sistema operativo.
  • Resultado: acceso root confirmado sobre la máquina Snakeoil.
